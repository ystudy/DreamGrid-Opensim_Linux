## New facts the spec should record
- The launcher holds `<data>/launcher.lock` (no sharing) for its lifetime: one launcher per data directory. The host exits 3 when another launcher holds it, 2 when the data directory or settings are unusable, 1 when the web port is taken. A refused lock leaves the data directory's permissions untouched (they are applied once the lock is held).
- Launcher verbs (first argument): `--version` prints the raw `InformationalVersion` (`0.0.0-dev+<sha>` for untagged builds); `admin-link --data <dir> [--wait <s>] [--open]` prints the setup link while setup is open, else the admin page, and never creates the settings (exit 4 when none appear in time).
- The REST console never resends a command the server accepted, and always drains late output once.
- An interrupted region setup is resumed: a region left running is adopted, never started twice, and a failed adoption never keeps the database and Robust down.
- Background work (warm-up, region setup, dashboard actions) is awaited at shutdown.
- "Stop all" clears the last start failure, so the dashboard shows a stopped world rather than "Your world could not start."
- The launcher writes a child's `.start` sidecar before its PID file.

## Open follow-ups

### Not done in version 1
- **linux-arm64 packages:** they need their own runner and install smoke.
- **Graceful quit at OS shutdown:** systemd and Windows end the children at machine shutdown (MariaDB shuts down cleanly on SIGTERM; OpenSim saves prims as they change). Intercepting shutdown to quit the region and Robust first is not done.
- **Windows CI runtime-change upgrade:** done in the final fix wave (release.yml builds a third installer with a relabelled `RUNTIME_VERSION` and runs the Windows smoke for both upgrades), but not run yet.

### Final fix wave, unverified until CI
- The Windows installer changes (`set-web-port`, the stays-up check after `sc start`, restarting the service from `DeinitializeSetup`, the pinned-binPath migration) are uncompiled; the Windows smoke's new `refused-port` and `web-port` stages have not run. The `DeinitializeSetup` restart, the stays-up failure path and a failing `set-web-port` (a port that collides with a changed Robust or region port) are not covered by any smoke.
- Debian: the "not active within 30 s" failure path of `install.sh` is not smoke-tested.
- `stop-grid` waits for every running process a PID file names, without the start-identity check, so a PID reused by an unrelated program holds it for the full 60 s (then exit 5; the uninstaller only logs it).

### Deferred minors still open
- **Settings, lock and ACL:** `InstanceLock` treats any `IOException` as "already running" (disk or path errors are misreported); the stale `.tmp` sweep flag is set even when the delete fails; `Save_does_not_retry_non_sharing_errors` only means something on Windows and there is no positive sharing-retry test; the libc `open`/`fsync` P/Invoke has no `SetLastError` and only `DllNotFound`/`EntryPointNotFound` are caught; `LauncherPathsTests.cs:57` misses a space after a comma; the folder's owner is not set (an admin creator keeps implicit WRITE_DAC); fully qualified `System.Security` names hurt readability; `Directory.CreateDirectory` sits outside the friendly-message try (still exit 2).
- **Processes and adoption:** the `StartMysql` comment in `LegacyCommandApi` overstates (the upgrade stop happens only on an idle grid); `KillTree` is gated on the PID file through `ReadLive`; no `ManagedProcess`-level reused-PID test and no `IsZombie` `UnauthorizedAccess` test; an orphaned `.start` sidecar after a child deletes its own PID file makes a later PID file written by something else be rejected; the `NOTIFY_SOCKET` test covers the helper only; no "unknown live StartId → reject" test. (Task 2's "2 s slack is thin" is resolved by the sidecar.)
- **Grid controller:** a region dying between `WillAdopt` and `StartAsync` starts a fresh region before the database and Robust (§6.6 order); an adopted unfinished region stays monitored when the database or Robust then fail; the adoption health wait delays the MariaDB start, and there is no test for an unfinished region with a pending upgrade; a console that refuses the login can delay the database by up to 300 s during adoption; an adoption failure is still shown after a later crash (Stop all now clears it).
- **INI values and the World page:** the Network page uses `Hostname ?? DetectedAddress`, not `HostAddress.Effective`; `SettingsValidator` does not run `GridNameError` (a hand-edited name bypasses it); the World page's empty-name branch is separate from `GridNameError`.
- **REST console:** the Debug logger is never wired at the construction sites; the 100 ms `LateOutputWait` is undocumented, and timing tests rely on it being above a 20 ms gate.
- **Shutdown and background work:** `Run` after a `StopAsync` snapshot is not awaited (pre-cancelled token); the `_stopping` CTS is not disposed; the test helper disposes its `LoggerFactory` early; no timeout-path test; the logger swallows formatter exceptions.
- **Website:** the allowlist test catches newly opened endpoints (the right invariant) but not undecided ones; the fallback policy builder is duplicated; unknown paths now answer 302/401 instead of 404 (untested); the start-failure box is duplicated on World and Avatar; the World page shows a failure on GET, not after submit; the duplicate-port message uses its own wording (the validator's labels name Robust).
- **Verbs:** `Version()` falls back to "dev", which the constraint does not word.
- **Packages:** the top-level `OpenSim.ini` is not excluded (the stager drops it anyway); test and tool binaries ship (pCampBot, `*Test*`); macOS and arm64 natives are in both packages; `$isLinuxPackage` is unused; no tarball-content assertion; the runtime is downloaded again on every run.
- **Debian installer:** no hint about `/opt/dreamgrid.old` after a failed upgrade; a partial unpack is left behind; raw curl and systemctl errors reach the user; `in_use` fails open when `/proc` is unreadable; the runtime folder's mode comes from the tarball (no explicit `chmod 755`); an existing runtime folder is trusted; two runtime copies on disk; installs from before the versioned runtime lose their old runtime on the second upgrade (none shipped).
- **Debian smoke and InstallSmoke:** no check of `/opt` permissions after an upgrade or of the download path (`DREAMGRID_RELEASE` included); InstallSmoke ignores the host of `--url`; the `nc` listener can race the probe; restrictive sudoers may drop `DREAMGRID_RELEASE`.
- **Windows installer:** `Check: ServiceRunning` timing for the finish checkbox; reinstalling into a folder that holds only leftover `dotnet-*`/`mariadb-*` folders is rejected; `SettingsWebPort` is a text match; the uninstall smoke does not assert that `{app}` is gone; watch for a name clash with a user-defined helper at the first compile.
- **Workflows and docs:** `contents: write` on the called workflow relies on release.yml's top-level `read` (add a comment or split later); the release notes' arrow wording; the spec's §4.13 tag format line; the Windows workflow steps lack explicit `$LASTEXITCODE` checks.
